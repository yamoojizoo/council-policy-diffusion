# 광역 지방의회 회의록 기반 지방정책 이슈 트렌드 분석 및 확산 흐름 예측

2026 DATA·AI 분석 경진대회 · 정책지정 문제(국회도서관)

## 1. 무엇을 하는가

| 단계 | 모듈 | 내용 |
|---|---|---|
| 전처리 | `src/preprocess.py` | 회의록 JSON(`RASMBLY_NM, MTGNM, MINTS_NM, MTG_DE, MINTS_HTML`)의 HTML을 텍스트로 바꾸고 발언자·발언 단위로 분할. 17개 의회의 서로 다른 발언자 표기(`○위원장`, `위원장 이용창`, `김용임 위원`, `↘ 국장 ○○○`, `위원장 윤 명 희`, 여러 줄로 쪼개진 표기)를 모두 처리. 회의록명·일자가 같아도 본문이 다른 별개 회의록이 많아 **본문 해시 기준으로만 중복 제거** |
| 이슈 도출 | `src/issues.py` | (A) 조례안 명칭에서 지역명을 떼어 정책 단위를 추출 (B) Kiwi 형태소 분석으로 명사구를 뽑아, 데이터 초기 구간에 없다가 3개 이상 의회에서 새로 등장한 표현을 '신규 이슈'로 선정 → 핵심어 일치·포함 관계 + 문장 임베딩 군집으로 동의 표현 병합 |
| 언급 색인 | `src/issues.py` | 모든 발언에서 이슈 언급을 찾아 회의록명·회의일자·발언자·원문 구간을 저장 |
| 최초 관측·전파 | `src/spread.py` | 의회별 최초 관측일 타임라인. 후속 의회마다 근거 유형을 **명시적 참조 / 비특정 참조 / 시간적 후행** 셋으로 구분. 상위법령·중앙정부 계기에 따른 '동시 대응' 가능성 별도 표시 |
| 확산 예측 | `src/predict.py` | (이슈 × 미관측 의회)별로 기준 시점 T까지의 정보만으로 특징을 만들고, T 이후 180일 안에 처음 관측될지를 로지스틱 회귀로 학습. 시점 이동 백테스트로 검증 후 분석 기준일 시점에서 예측 |
| 지도 데이터 | `tools/build_geo.py` → `src/korea_geo.json` | 통계청 시·도 경계(2013)를 대시보드용 SVG 경로로 경량화 (시각화 전용) |
| 대시보드 | `src/dashboard.py` | 결과를 오프라인 인터랙티브 HTML로 시각화 (외부 라이브러리 없음, 라이트/다크 모드) |
| 보고서 | `src/report.py` | 이슈를 **A. 점진 확산형**(시차를 두고 퍼짐 → 전파 경로 분석) / **B. 동시다발형**(절반 이상이 60일 안에 등장 → 공통 외부 계기로 해석, 경로 추정 안 함) / **부록: 상시 이슈**(데이터 첫 90일 안에 이미 존재 → 최초 등장 판단 불가)로 나눠 서술. 결산·예산·감사 시즌마다 반복되는 계절성 표현은 제외 |

### 문제 조건 대응
- **최초 등장 = 제공 데이터 범위 내 최초 관측**: 보고서 전체에 명시하고, 데이터 이전 논의 여부는 판단하지 않음.
- **인과 단정 금지**: 이슈가 언급된 문장(앞뒤 1문장)에 '타 광역 지명 + 30자 이내 선행사례 단서어(사례·벤치마킹·처럼·이미 시행·추진하고 있 등)' 구조가 있을 때만 '명시적 참조'로 경로를 표시. 지명이 대학·교육청·지역 묶음(대구·경북 등)을 가리키는 경우는 제외. 참조 대상 의회의 관측이 데이터상 더 늦으면 경고 문구를 붙임. 참조 표현이 없으면 '시간적 선후만 확인'으로만 기술.
- **근거 제시**: 모든 판단에 회의록명, 회의일자, 발언자, 원문 구간을 붙임.
- **분석 기준일 준수**: 예측 특징은 기준 시점 이전 회의록만 사용함. 최종 예측 기준일은 제공 데이터의 마지막 회의일자.
- **상용 LLM API 미사용**: 모든 처리는 로컬에서 실행되며 데이터가 외부로 전송되지 않음.

## 2. 실행 방법

```bash
pip install -r requirements.txt
# 국회도서관 국가학술정보 클라우드에서 받은 회의록 JSON을 data/ 아래에 둔다 (하위 폴더, .json/.json.gz/.jsonl 허용)
python run_pipeline.py --data_dir data --out_dir output
```

주요 옵션

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--embed_model` | `jhgan/ko-sroberta-multitask` | 이슈 병합용 문장 임베딩 모델. `""`이면 문자 n-gram TF-IDF |
| `--no_kiwi` | off | Kiwi 대신 규칙 기반 명사구 추출 |
| `--min_df` / `--min_asm` | 8 / 3 | 신규 키워드의 최소 회의록 수 / 최소 의회 수 |
| `--horizon_days` | 180 | 확산 예측 기간 |
| `--top_n` | 15 | 보고서에 서술할 이슈 수 |
| `--reuse` | off | 저장된 전처리 결과 재사용 |

### 출력물
- `output/dashboard.html`: **인터랙티브 대시보드** (단일 HTML, 인터넷·서버 불필요, 브라우저로 바로 열기). 개요(대표 이슈가 실제 지도 위에서 월별로 번지는 과정 재생), 이슈(확산 재생 지도·누적 채택 곡선·월별 언급·근거 원문·확산 예측), 의회(의회별 처음 꺼낸 이슈·혁신성 순위), 예측 모델 검증. 라이트/다크 모드, 모바일 대응
- `output/report.md`: 항목별 서술형 보고서 (①핵심 이슈 ②최초 관측 ③후속 논의 흐름 ④향후 확산 가능성 + 해석 유의사항)
- `output/results.json`: 위 내용의 기계가독 버전과 모델 검증 지표
- `output/forecast_all.csv`: 모든 (이슈, 미관측 의회)의 예측 점수
- `output/issue_dictionary.json`: 이슈 사전(대표 명칭, 유사 표현, 매칭 표면형)
- `output/work/`: 중간 산출물(발언 테이블, 언급 색인)

### 스모크 테스트 (가짜 데이터)
```bash
python tests/make_synthetic.py data_synth
python run_pipeline.py --data_dir data_synth --out_dir output_synth --embed_model ""
```
확산 패턴을 미리 심어 둔 가짜 회의록으로 이슈 4개, 최초 관측 의회, 명시적 참조 경로, 동시 대응 표시가 복원되는지 확인한다. **실제 분석 결과가 아니다.**

## 3. 사용한 외부 모델·자료

| 명칭 | 버전 | 용도 | 적용 범위 |
|---|---|---|---|
| kiwipiepy (Kiwi 한국어 형태소 분석기) | 0.24.1 | 명사구 추출 | 신규 키워드 후보 생성 |
| jhgan/ko-sroberta-multitask (선택) | Hugging Face 공개 모델 | 이슈 명칭 임베딩 | 동의 표현 병합. 로컬 실행 |
| scikit-learn LogisticRegression | 1.9.1 | 확산 예측 | 이슈×의회 확산 확률 |
| 광역 시·도 인접 관계 | 작성자 구성(행정구역 경계 기준) | 예측 특징 '인접 의회 관측 비율' | 예측 단계 보조 변수 |

상용 LLM API는 사용하지 않는다.

## 4. 한계
- 회의록 HTML 구조가 의회별로 다르면 발언자 분리 규칙(`○` 표식)을 보정해야 할 수 있다.
- 명시적 참조 탐지는 지명과 단서어가 같은 문맥 창(±320자)에 함께 나오는지로 판정하는 규칙 기반이므로, 오탐 가능성이 있는 사례는 보고서 원문 인용으로 사람이 확인할 수 있게 했다.
- 예측 점수는 과거 회의록 패턴에 기반한 추정치이며 의회의 정책 결정을 예단하지 않는다.


## 5. 데이터 취급
주최 측 제공 데이터는 경진대회 이외의 목적으로 사용할 수 없으므로, 원본 데이터와 원문 인용이 포함된 분석 결과(`data/`, `output/`)는 저장소에 포함하지 않는다(`.gitignore`). `examples/`의 보고서·대시보드는 **가짜(합성) 회의록**으로 만든 시연용이다.
