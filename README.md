# 광역 지방의회 회의록 기반 지방정책 이슈 트렌드 분석 및 확산 흐름 예측

**팀 ripple** · 2026 DATA·AI 분석 경진대회 문제해결 부문 · 정책지정 문제(수요기관: 국회도서관)

17개 광역의회 회의록 9,886건(2024.1.3~2025.12.31)을 발언 3,114,437개로 나눠, 기간 중 새로 떠오른 정책 의제 158개를 찾습니다. 의제마다 의회별 최초 관측과 후속 논의 순서를 추적하고, 후속 의회마다 인과 추론 조건(Campbell)과 과정추적 검정에 따른 **증거 등급**을 매깁니다. 다음 6개월 안에 의제를 다룰 의회도 예측합니다.

- 확산 예측(시점 이동 검증): ROC-AUC 0.625. 점수 상위 10% 적중률이 무작위의 1.7배, 조례 의제는 2.3배입니다.
- 사후 검증: 2025.9.30 시점 예측을 모델이 보지 않은 이후 92일과 대조했습니다. '높음' 등급의 18.4%가 실제로 논의를 시작했습니다(평균 9.6%, ROC-AUC 0.663).
- 모든 판단에 회의록명·회의일자·발언자·원문이 붙습니다.
- 상용 AI API 없이 일반 PC에서 재현됩니다.

방법과 결과의 상세는 [`TECHNICAL_DOC.md`](TECHNICAL_DOC.md)(결과보고서)에 정리했습니다.

| ② 이슈 후보 | `src/issues.py` | (A) 조례안 의안명 정규화(정밀도) + (B) 신규 명사구(재현율). 3개 이상 의회·8건 이상, 통계적 신규성 검정 (1-q)^df < 5%, 화제성 | 조례안 5,516 + 신규 키워드 1,500 |

### 2.1 확산 예측 모델(학습·평가·추론)
- **예측 단위와 라벨**: (이슈, 아직 관측되지 않은 의회) 쌍입니다. 기준 시점 T 이후 180일 안에 그 의회에서 처음 관측되면 1입니다.
- **특징 13개**: 모두 T 이전 정보만 씁니다.

  | 범주 | 특징 |
  |---|---|
  | 확산 규모·속도 | 기관측 의회 수·비율, 최근 90일 신규 관측 수, 경과 기간 |
  | 인접 광역 | 관측 비율, 최근 신규 관측 수 |
  | 관심도 추세 | 최근 180일 언급량, 증가율 |
  | 의제 유사도 | 평균, 최대 |
  | 의회 성향 | 최근 신규 의제 수용 수, 회의 수 |
  | 이슈 성격 | 조례 여부 |

- **학습 표본**: 기준 시점 T를 60일 간격으로 옮기며 만듭니다. 전체 데이터 기준 151,677건입니다(`src/predict.py: build_train`).
- **평가(시점 이동 검증)**: 2024.12~2025.6의 4개 기준 시점(60일 간격)마다, 라벨 기간(T+180일)이 그 시점 이전에 끝난 표본으로만 학습해 미래 정보를 차단합니다.
  - ROC-AUC 0.625(조례 의제 0.648)
  - 상위 10% 적중률 26.8%(기저 15.7%)
  - 선정 누수 점검: ROC-AUC 0.606
- **사후 검증**: `--until 2025-09-30`으로 처음부터 다시 분석·예측한 뒤, 이후 92일(회의록 2,735건)과 대조했습니다.
  - 높음 18.4% · 보통 13.9% · 낮음 7.1%(평균 9.6%)
  - ROC-AUC 0.663
- **추론**: 마지막 회의일(2025.12.31) 기준으로 모든 (이슈, 미관측 의회) 쌍에 점수를 매깁니다.
  - 상위 10%는 '높음', 다음 20%는 '보통'입니다.
  - 기여도가 큰 특징 3개를 이유 문장으로 붙입니다.
  - 결과는 `forecast_all.csv`에 저장합니다.
- **모델 파일** `model/`
  - `forecast_model.joblib`: scikit-learn 파이프라인과 특징 목록. 사용법:
    ```python
    import joblib
    m = joblib.load("model/forecast_model.joblib")
    p = m["model"].predict_proba(X[m["features"]])[:, 1]
    ```
  - `forecast_model.json`: 특징별 평균·표준편차·계수와 절편. 라이브러리 없이도 점수 공식을 확인할 수 있습니다.
  - 저장된 모델로 다시 계산한 점수는 `forecast_all.csv`와 차이가 1e-16 이하입니다.

## 4. 실행 방법

### 4.1 더블클릭(권장)
1. `data/`에 회의록 JSON을 넣습니다.
2. 윈도우는 `run_windows.bat`, 맥은 `run_mac.command`를 더블클릭합니다.
3. 다음 순서로 자동 진행됩니다.
   1. 실행 전 점검: Python 버전, 데이터 위치
   2. 라이브러리 설치
   3. 2025.9.30 시점 분석(`output_prev/`)
   4. 전체 분석과 사후 검증(`output/`)
   5. 대시보드 열기

### 4.2 명령줄
```bash
pip install -r requirements-lock.txt        # 또는 requirements.txt (+ requirements-optional.txt)
python run_pipeline.py --data_dir data --out_dir output_prev --until 2025-09-30 --cache cache   # 사후 검증용 지난 시점
python run_pipeline.py --data_dir data --out_dir output --prev_out output_prev --cache cache     # 최종 분석
```
사후 검증이 필요 없으면 두 번째 줄만 `--prev_out` 없이 실행하면 됩니다.

### 4.3 Jupyter Notebook(학습·평가 과정 확인)
```bash
pip install -r requirements-notebook.txt
cd notebooks && jupyter notebook 01_전체_분석_과정.ipynb
```
노트북은 다음을 단계별로 실행하고 결과를 그림으로 보여 줍니다(약 20분).
1. 데이터 불러오기·전처리
2. 이슈 추출
3. 병합·색인
4. 증거 등급
5. **모델 학습·시점 이동 평가**
6. **모델 저장·불러오기·추론**
7. 가설 검증
8. **사후 검증**
9. 보고서·대시보드

노트북은 `src/`의 같은 함수를 호출하므로 결과는 `run_pipeline.py`와 같습니다. 경로는 환경변수 `DATA_DIR`, `CACHE_DIR`, `OUT_DIR`, `PREV_DIR`로 바꿀 수 있습니다. 노트북 원본은 `scripts/make_notebook.py`로 만듭니다.

**참가자 주요 기여 및 검증**

| 구분 | 참가자가 직접 판단·선택·요구·검증한 내용 |
|---|---|
| 과제 선정과 데이터 확보 | 경진대회 정책지정 문제 중 국회도서관 과제를 선택했다. 17개 광역의회 2024·2025년 회의록 데이터(JSON 36개 파일)를 직접 구해 분석 환경에 올렸다. 공공인재학부 전공 관점에서 '지방의회는 정책 실험실이고, 여러 지역으로 번지는 조례는 입법 수요의 신호'라는 문제의식을 분석 방향으로 삼았다 |
| 선행연구 검토와 이론 학습 | 정책확산 관련 논문(Berry & Berry 1990, Walker 1969, Volden 2006, Shipan & Volden 2008, Kingdon 1984, Downs 1972, Bass 1969 등)을 직접 읽고 분석해, 이 데이터로 검증할 수 있는 이론 틀을 골랐다. 인과 추론(Campbell)과 과정추적의 증거 검정을 공부해, 확산 경로 판정 규칙이 이론적으로 타당한지 검토했다 |
| 이론 틀 설정 | 사회과학 이론을 적극 활용하는 방향을 정했다. 전공 수업에서 배운 Campbell의 인과 추론 조건을 확산 경로 판정에 적용하자고 제안했고, 이 밖에 쓸 수 있는 이론 틀을 검토하게 해 정책확산 이론(지역확산·학습·혁신성·수직적 확산·이슈관심주기·Bass 모형)을 가설 H1~H6으로 세우고 실제로 검정하도록 했다 |
| 판정 원칙 정제 | 명시적 참조 판정 원칙을 '논리적으로 어떻게 해결할지' 다시 따져 다듬도록 요구해, 시간적 선행·대상 일치·도입 시점 근접성·참조 방향 조건이 들어갔다 |
| 방법론 한계 극복 요구 | Bass 모형의 순환논리와 이슈별 식별 문제를 '극복할 수 없는지' 물어, 채택 시점을 쓰지 않는 텍스트 기준 분할·부분 풀링 등 보완 분석이 추가됐다 |
| 검증 설계 | 결과보고서에 넣을 정밀도 표본 검증과 외부 통계(KOSIS) 통제 실험을 요구했다. 새 회의록이 들어올 때의 갱신 흐름을 고르면서, 과거 시점 예측을 이후 실제와 대조하는 사후 검증(ROC-AUC 0.663)이 만들어졌다 |
| 전수 점검 | 결과물 전체를 '낱낱이 뜯어보고 오류를 고치자'고 지시하고, 그 결과로 찾은 오류(아래 실패사례)의 수정 내용을 검토했다 |
| 이용자 설계 | 대상 이용자(국회·지방의회·행정·연구)를 정의하고, 첫 화면에서 이용 목적을 고르면 그에 맞는 화면이 열리는 구조를 직접 제안했다. 역할별 화면을 더 발전시키도록 요구했다 |
| 기능 선택 | 제안된 기능 후보 중 확산 단계·지켜볼 의회·조례안 표시·둘러보기, 원문 검색·모바일 대응, 판정 근거 체크리스트·분석 깔때기·시점 슬라이더·빠른 이동·글꼴 내장을 직접 골랐다 |
| 결과 표시 원칙 | 정밀도 수치와 가설 검증 결과는 대시보드가 아니라 보고서에 두도록 결정했다. 디자인은 여러 대안을 비교한 뒤 현재 톤을 강화하는 방향을 선택했다 |
| 재현 검증 | 본인 윈도우 PC에서 처음부터 실행했다. Python 3.15 설치 실패, 메모리 부족 같은 문제를 직접 겪고 보고해 실행 스크립트를 고치게 했고, 지난 시점 분석 단계의 회의록·발언·이슈 수와 예측 지표가 같음을 확인한 뒤 최종 분석과 대시보드 생성까지 완료했다. 이 과정에서 두 단계를 더블클릭 한 번으로 실행하는 방식을 결정했다 |
| 제출물 구성 | 제안서를 '문제의식 → 연구 흐름 → 결과'가 이어지도록 그림과 함께 구성하자는 아이디어, 한 장 요약 이미지, 발표용 덱 제작, 데모영상의 연출 방향(모던한 광고형, 기능과 의미를 설명하는 자막, 배경음악)을 정했다. 팀명과 최종 제출물 구성을 결정하고 표현을 검토했다 |

**검토한 대안 및 실패사례**

| 시도 | 문제 | 조치 |
|---|---|---|
| 명시적 참조를 '다른 지역명 + 단서어'로 넓게 판정 | 119건이 잡혔지만 다른 사업·공동 추진·사후 언급이 섞임 | 시간적 선행, 대상 일치, 180일 이내, 참조 방향 조건을 더함. 신규 의제 기준 3건으로 줄었고 정밀도가 올라감. 30~365일 민감도 분석에서 결론 동일 |
| 신규 키워드를 부분 문자열로 매칭 | 단어 중간 조각이 무관한 문장과 매칭됨(예: '위기선제') | 단어 경계가 아닌 표현 자동 제거 |
| 예측 모델 계수로 '의제 유사 지역 학습'을 해석 | 최대·평균 유사도의 다중공선성 때문에 효과가 부풀려 보임 | 이론 검증 모형을 분리(VIF 확인) → H2 기각으로 정정 |
| 정점 이후 관심 감소를 단순 비교 | 정점을 최댓값으로 정의하면 감소가 기계적으로 생김 | 월 순서를 섞은 무작위 기준과 비교(순열 검정) → H5 기각으로 정정 |
| 문장 임베딩(ko-sroberta)으로 이슈 병합 | 모델 내려받기·환경에 따라 결과가 달라질 수 있음 | 기본값을 문자 n-gram TF-IDF로 고정, 임베딩은 선택 옵션 |
| KOSIS 지역 특성 4개를 예측 특징에 추가 | 성능 차이 ±0.006 이내 | 기본 모델 미채택, 통제 실험 결과로만 보고 |
| 2년 전체로 만든 이슈 사전으로 예측 검증 | '결국 퍼진 이슈'만 남아 성능이 부풀 수 있음 | 기준 시점에 이미 3곳 이상인 표본만으로 재검증(ROC-AUC 0.606), 이후 시점을 잘라 처음부터 다시 분석하는 사후 검증 추가 |
| 사건 의제의 최초 관측 | 2024.11 회의록의 과거 탄핵 언급이 '대통령 탄핵' 최초 관측으로 잡힘 | 사건 시작일 규칙(`config/issue_start.txt`) |

| 윈도우 실행 | Python 3.15 설치 실패, 병렬 읽기 메모리 부족, 폴더명 괄호로 스크립트 중단 | Python 버전 우선순위, 메모리 기반 병렬 수·열 단위 처리·캐시, 스크립트 재작성 |

**최종 선택 이유**
- **해석 가능성**: 확산 예측은 국회·지방의회 실무자가 '왜 이 의회인가'를 확인할 수 있어야 하므로, 계수와 이유 문장을 제시할 수 있는 로지스틱 회귀를 택했습니다. 예측 성능이 중간 수준(ROC-AUC 0.6대)이라는 점은 등급(순위)으로 제시해 보완했습니다.
- **문제 조건 충족**: 인과 단정 금지 조건 때문에 확산 경로는 증거 등급 체계로 판정합니다. 근거가 약하면 '시간적 후행'으로 남기는 보수적 설계입니다.
- **재현성과 운영 가능성**: 로컬 실행, 무료 라이브러리, 상용 API 미사용으로 수요기관이 그대로 운영할 수 있습니다.

모든 수치와 판정은 원문 표본 대조(`validation/precision_sample.md`), 단위 테스트, 두 환경 재실행으로 확인했습니다.

## 7. 한계
- **명시적 참조 탐지**: 규칙 기반이라 재현율이 낮습니다. 놓친 참조는 '시간적 후행'으로 남을 뿐 잘못된 인과 주장은 생기지 않습니다.
- **최초 관측의 범위**: '최초 관측'은 제공 데이터 범위 안의 첫 등장입니다. 데이터 시작 후 90일 안에 이미 있던 의제는 상시 이슈로 분리했습니다.
- **예측 점수의 성격**: 과거 회의록 패턴에 기반한 추정치이며, 의회의 정책 결정을 예단하지 않습니다.
- **조례안 집계 기준**: 조례안 집계는 의안명 기준입니다. 의제 이름과 다른 제목으로 발의된 조례안은 '조례안으로 다룬 의회' 수에서 빠질 수 있습니다.

- 주최 측 제공 데이터는 경진대회 이외의 목적으로 사용할 수 없으므로, 원본 데이터는 저장소와 제출 묶음에 포함하지 않았습니다.

- `examples/`는 합성 회의록으로 만든 시연용입니다.
- 개인정보, API Key, 비밀번호는 포함되어 있지 않습니다. 회의록에 나오는 발언자 이름은 공개 회의록에 기재된 공직자 표기 그대로입니다.
